Paradigm 2: Native Caddy JSON

Why native JSON is the true internal engine of Caddy v2, and why standardizing on /etc/caddy/caddy.json unlocked programmatic safety and zero-downtime operations across our fleet.

Official Upstream Reference: Upstream Caddy JSON structure and the RESTful Admin API.
caddyserver.com/docs/json/ ↗ • caddyserver.com/docs/api ↗

🏛️ The True Architecture of Caddy v2

Unlike older web servers whose core is tied to proprietary syntax, Caddy v2 was designed from day one around a modular Go architecture. Caddy core does not parse text config files directly; instead, Caddy core takes a JSON document and deserializes it directly into Go structs.

// Caddy Core Configuration Pipeline
[ Inbound Configuration ] ──► JSON Document ──► Go Deserializer ──► In-Memory Active Server

🚀 Core Superpowers of Native JSON

Superpower 1

Zero-Downtime Hot Reloads

When you reload Caddy using caddy reload --config /etc/caddy/caddy.json, Caddy compares the new JSON AST against the running memory state. It spins up new listeners and shuts down obsolete handlers without terminating active TCP sockets. Active WebSockets and streaming calls experience zero disruption.

Superpower 2

Programmatic AST Manipulation

Because it is pure JSON, any programming language (Node.js, Python, Go) can load it via JSON.parse(), find routes with precise object traversals or JSONPath queries, insert or delete route objects, and serialize it back with JSON.stringify(). No regex or string hacking required.

Superpower 3

Direct Admin API Integration

Caddy exposes a RESTful Admin API on port 2019. You can query running routes (GET http://localhost:2019/config/apps/http/servers/srv0/routes) or patch an individual subdomain route dynamically with a single POST or PATCH request.

Superpower 4

Atomic Backup Safety

Before any mutation script touches /etc/caddy/caddy.json, it creates a timestamped copy: caddy.json.bak.<timestamp>. If Caddy's validation fails during reload, the system rolls back instantaneously with zero state corruption.

📋 Production Benchmark: Caddyfile vs Native JSON

Operational Dimension Caddyfile Adapter Native Caddy JSON
Single Source of Truth No (Adapter layer) Yes (Canonical internal format)
Programmatic Scripting Fragile (String / Regex parsing) Reliable (Native JSON Object AST)
Admin API (localhost:2019) Incompatible with live text edits Native API payload format
Active WebSocket Retention Often dropped if systemctl restarted Preserved across hot reloads
Fleet Port Auditability Manual text scan Instant automated extraction (caddy-cli)
Human Readability High (Concise text) Low (Deeply nested JSON structures)
The Friction Point: Human Readability
Look at the last row of the table: Human Readability. Native Caddy JSON is extraordinarily powerful for machines and APIs, but severely unreadable for human operators. That friction is why we built our suite of tools.
