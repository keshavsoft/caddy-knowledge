Why We Built Tools on Native JSON

Standardizing on native Caddy JSON solved fleet automation and zero-downtime reliability, but created severe cognitive friction for human developers. Here is the story of how our four specialized micro-tools resolved that tension.

🧠 The Dilemma: "JSON is the Best Machine Format, but the Worst Human Format"

In Caddy, configuring a standard reverse proxy with a WebSocket upgrade requires writing 25 lines of nested JSON: 

{
  "match": [{ "host": ["appointment.keshavsoft.com"] }],
  "handle": [{
    "handler": "subroute",
    "routes": [{
      "handle": [{
        "handler": "reverse_proxy",
        "upstreams": [{ "dial": "localhost:3000" }]
      }]
    }]
  }],
  "terminal": true
}

When you run 15 subdomains on an Ubuntu VPS, /etc/caddy/caddy.json quickly expands past 800 lines of nested brackets. This created two serious operational problems:

1. The "Cold-Start Amnesia" Trap

Developers only configure reverse proxies once every few months when provisioning a new microservice. When returning after 90 days, nobody remembers the exact nesting sequence (match ➔ host ➔ handle ➔ subroute ➔ routes ➔ handle ➔ reverse_proxy ➔ upstreams ➔ dial). Minor bracket mistakes risk invalidating the configuration.

2. The Blind Port Allocation Guesswork

Before launching a new Node.js service, the developer asks: "Can I use port 3000? Is 3001 already routed to another subdomain? What about 8080?" Finding the answer required scrolling through hundreds of lines of raw JSON, leading to port collision accidents.

🛠️ The Solution: 4 Focused Micro-Tools

Instead of returning to the brittle Caddyfile or building a complex web management UI, KeshavSoft engineered four single-purpose CLI micro-tools that run directly in your terminal via npx:

1. caddy-cli

Observability

The Human Lens: Parses live caddy.json and instantly outputs clean terminal tables showing all active subdomains, upstreams, and dialed ports. 

npx caddy-cli -p
Explore caddy-cli →

2. caddy-template

Blueprint Generation

The Schema Blueprint: Never hand-write JSON ASTs. Emits battle-tested, validated JSON route blocks for proxy, ws-split, static, and multi-host. 

npx caddy-template proxy appointment.keshavsoft.com 3000
Explore caddy-template →

3. caddy-subdomain

Verification Engine

Two-Stage Verification: Injects a zero-dependency in-memory smoke probe (static_response: 200 OK) to verify GoDaddy DNS and Let's Encrypt TLS before code or ports exist. 

npx caddy-subdomain probe call.keshavsoft.com
Explore caddy-subdomain →

4. caddy-fileserver

Filesystem Bridge

Ubuntu Disk Automation: Automatically provisions /usr/share/<domain>, creates responsive starter HTML, and injects Caddy file_server routes in one step. 

npx caddy-fileserver init call.keshavsoft.com
Explore caddy-fileserver →
The Complete Story in a Nutshell
We did not abandon the Caddyfile because we disliked it; we graduated from it because our production fleet demanded programmatic safety and zero downtime. By standardizing on Native Caddy JSON and building focused micro-tools, we get 100% machine safety with 100% human clarity.
