The Story: The Two Paradigms of Caddy

To understand the KeshavSoft Caddy ecosystem, you must understand the architectural fork in Caddy: the human-facing Caddyfile text configuration versus the machine-native JSON single source of truth.

Official Upstream Reference: Caddyserver defines the Caddyfile merely as an adapter converting text into native JSON.
caddyserver.com/docs/getting-started ↗

⚖️ The Two Ways to Drive Caddy

When developers first encounter Caddy, 99% of tutorials instruct them to write a Caddyfile. This creates a fundamental misconception that Caddy is a text-configured server like Nginx or Apache. In reality, Caddy is a dynamic, JSON-native application platform with two distinct operating paradigms:

1. The Caddyfile (Text Config)

Adapter Layer

A declarative, human-tailored syntax designed for quick manual text editing. Under the hood, Caddy compiles it into JSON before running it.

  • Great for beginners and single-website setups
  • Brittle for programmatic automation
  • Requires text parsing and regex hacking for scripts
  • Disconnected from Caddy's dynamic REST Admin API
Read Caddyfile Adapter Deep-Dive →

2. Native Caddy JSON

True Source of Truth

Caddy’s native internal architecture. Every feature, handler, matcher, and upstream dial is natively modeled as a JSON Abstract Syntax Tree (AST).

  • Zero-downtime hot reloads in memory
  • Directly drives Caddy’s Admin API (:2019)
  • 100% scriptable and safe for automation pipelines
  • Intimidatingly deeply nested for human operators
Read Native JSON Paradigm Deep-Dive →

🔄 The Architectural Evolution at KeshavSoft

Managing dozens of microservices, WebSockets, and static documentation sites across our Ubuntu VPS fleet revealed the inherent scaling limit of Caddyfile text editing:

// Phase 1: Manual Caddyfile (Cold-Start Amnesia)
- Developer manually SSHs into VPS, opens /etc/caddy/Caddyfile in nano
- Accidentally introduces syntax typo or breaks an existing subdomain block
- systemctl restart drops active WebSockets across all production subdomains

// Phase 2: The Decision to Standardize on Native JSON
+ Make /etc/caddy/caddy.json the definitive, immutable source of truth
+ Use 'caddy reload --config /etc/caddy/caddy.json' for zero-downtime updates
! Problem: JSON is too verbose and deeply nested for human operators to audit

// Phase 3: Building The KeshavSoft Caddy JSON Toolchain
✓ caddy-cli: The Human Lens to inspect ports & routes at a glance
✓ caddy-template: Generates battle-tested JSON AST blueprints
✓ caddy-subdomain: Two-stage smoke probes & zero-downtime promotion
✓ caddy-fileserver: Automated Ubuntu filesystem & static file_server bridge
