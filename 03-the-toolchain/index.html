The KeshavSoft Caddy JSON Toolchain

Instead of maintaining a massive monolithic CLI or fragile text bash scripts, KeshavSoft split Caddy cloud operations into four specialized, complementary micro-tools.

🧩 How the Four Repositories Complement Each Other

[ Production Ubuntu VPS Fleet: /etc/caddy/caddy.json ]
caddy-cli
Read & Audit Lens
• Port mapping table (-p)
• Domain inspector (-d)
caddy-template
Route AST Generator
• proxy (single port)
• ws-split (dual-port)
• static & multi-host
caddy-subdomain
Lifecycle & Probes
• probe (DNS/SSL check)
• add (promote to reverse proxy)
caddy-fileserver
Filesystem Bridge
• /usr/share/<domain>
• init starter HTML
• file_server routes

📋 The 4 Tool Responsibilities

Tool Name Primary Responsibility Canonical NPX Invocation GitHub Repository
caddy-cli Human observability, fleet port allocation, route inspection npx caddy-cli -p keshavsoft/caddy-cli ↗
caddy-template Pure AST route blueprint emission for common server patterns npx caddy-template proxy <host> <port> keshavsoft/caddy-template ↗
caddy-subdomain Level-1 zero-dependency smoke test probes & route promotion npx caddy-subdomain probe <host> keshavsoft/caddy-subdomain ↗
caddy-fileserver Disk scaffolding, starter templates, and Caddy file_server bridge npx caddy-fileserver init <host> keshavsoft/caddy-fileserver ↗

⚡ The Typical Operator Journey

  1. Step 1 (Find Free Port): Run npx caddy-cli -p to check all ports currently occupied by Caddy routes and find an open slot (e.g. 3000).
  2. Step 2 (Verify DNS & TLS): Run npx caddy-subdomain probe new.keshavsoft.com to verify the domain resolves and gets a green HTTPS padlock without starting any app code.
  3. Step 3 (Deploy & Promote):
    • If static: run npx caddy-fileserver init new.keshavsoft.com to scaffold /usr/share/new.keshavsoft.com and wire static serving.
    • If dynamic Node.js: run npx caddy-subdomain add new.keshavsoft.com 3000 to promote the route to dial the backend service.
