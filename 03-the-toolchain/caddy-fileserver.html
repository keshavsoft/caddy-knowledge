caddy-fileserver: Ubuntu Filesystem Bridge

The Missing Half of Static Cloud Hosting: Bridges Caddy's public TLS listener (:443) directly to the Ubuntu filesystem (/usr/share/...) with complete 5-step automation.

Official Package & Repository: Published on npm and GitHub with interactive browser catalog.
npm: caddy-fileserver ↗ • github.com/keshavsoft/caddy-fileserver ↗

🌉 The Two Halves of Static Hosting

Static hosting on an Ubuntu VPS requires coordinating two separate environments:

1. The Front-Door Gateway: /etc/caddy/caddy.json (TLS termination, SNI matching, file_server handler)
↓ vars.root
2. The Ubuntu Filesystem: /usr/share/<domain> (Physical disk folder, HTML files, CSS, JS assets)

⚡ The 5-in-1 Atomic Command: `init`

Instead of manually running mkdir, creating test HTML, editing Caddy JSON, reloading, and curling the domain, caddy-fileserver init executes all five operations atomically: 

npx caddy-fileserver init call.keshavsoft.com

What It Does Under the Hood:

  1. Creates directory /usr/share/call.keshavsoft.com.
  2. Writes a modern, responsive starter index.html.
  3. Generates an atomic backup: caddy.json.bak.<ts>.
  4. Injects vars.root + file_server into Caddy JSON.
  5. Triggers hot reload and probes live endpoint.

Alignment Audit: `check`

Audits whether disk directories and Caddy JSON routes match: 

npx caddy-fileserver check call.keshavsoft.com
Disk Directory: Exists (/usr/share/call.keshavsoft.com)
Caddy Route: Aligned (vars.root + file_server)
Status: HEALTHY
