Emergency Troubleshooting: 502 Bad Gateway & Ports

Deterministic triage procedures for the three most common VPS reverse proxy failures: 502 Bad Gateway, internal port collisions, and DNS propagation lag.

🚨 Issue 1: 502 Bad Gateway

The Anatomy of a 502 in Caddy:

A 502 Bad Gateway means Caddy successfully terminated TLS on port 443, matched the hostname, and attempted to dial the internal upstream (e.g. localhost:3000), but the operating system returned Connection Refused (ECONNREFUSED).

The problem is ALWAYS with the backend process, NOT with Caddy or DNS!

Diagnostic Steps:

  1. Test internal listener: 
    curl -v http://localhost:3000
  2. Check if systemd service is active: 
    sudo systemctl status appointment-notifier
  3. Inspect application crash logs: 
    sudo journalctl -u appointment-notifier -n 50 --no-pager

⚔️ Issue 2: Port Collision (EADDRINUSE)

When launching a new service, Node.js crashes with Error: listen EADDRINUSE: address already in use :::3000.

Resolution:

  1. Run npx caddy-cli -p to see which domain is currently using that port in Caddy.
  2. Check the local Linux process bound to that port: 
    sudo ss -tulpn | grep :3000
  3. Pick an open port slot (e.g. 5000) and update the service configuration.

⏳ Issue 3: DNS Propagation Delays

The browser shows ERR_NAME_NOT_RESOLVED or Let's Encrypt fails with ACME challenge timeout.

Resolution:

dig +short call.keshavsoft.com @8.8.8.8

If no IP is returned, GoDaddy DNS propagation is still ongoing. Run npx caddy-subdomain probe call.keshavsoft.com to monitor when DNS and Let's Encrypt TLS successfully establish.
