Stage 2: Static File Server Promotion

Transitioning a verified subdomain from an in-memory smoke probe into a production static file server serving files from the Ubuntu filesystem with zero Node.js memory overhead.

🚀 The Promotion Command

Once Stage 1 is verified live, promote the subdomain with: 

npx caddy-fileserver init call.keshavsoft.com

What Happens Atomically During Promotion:

  1. caddy-fileserver creates the folder /usr/share/call.keshavsoft.com on Ubuntu disk.
  2. Scaffolds a responsive, mobile-ready starter index.html.
  3. Backs up /etc/caddy/caddy.json to a timestamped backup file.
  4. Replaces the Stage 1 static_response handler with a dual handler chain:
    • vars.root: /usr/share/call.keshavsoft.com
    • file_server: native zero-copy kernel file delivery
  5. Executes hot-reload. Existing TLS certificates remain active without re-issuance!

🔍 Verification & Audit

Verify that disk directories and Caddy JSON routes are perfectly synchronized: 

npx caddy-fileserver check call.keshavsoft.com
