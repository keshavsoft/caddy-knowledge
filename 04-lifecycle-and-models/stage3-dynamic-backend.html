Stage 3: Dynamic Node Backend Application

Promoting a subdomain to a full dynamic Node.js, Python, or Go microservice with internal port allocation, systemd supervision, and Caddy reverse proxy tunneling.

🔄 The Promotion Flow

Step 1: Check Open Ports

Run npx caddy-cli -p to inspect all ports dialed by Caddy routes and identify an unused port (e.g. 5000).

Step 2: Bind Systemd Service

Launch your Node.js application under systemd supervision (e.g. via ubuntu-service-cli) listening on localhost:5000.

🚀 Execute Route Promotion

Promote the Caddy route from the Stage 1 smoke probe or Stage 2 static server to dial the live Node.js process: 

npx caddy-subdomain add call.keshavsoft.com 5000

Under the Hood:

caddy-subdomain generates the reverse_proxy AST with upstreams: [{"dial": "localhost:5000"}], backs up caddy.json, and hot-reloads Caddy in memory.

Because TLS was already issued in Stage 1, the public traffic switches to the Node.js backend with zero certificate downtime.
