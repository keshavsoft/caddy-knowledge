The 3-Stage VPS Subdomain Maturity Model

Never configure DNS, Node.js ports, Caddy routes, and SSL simultaneously. KeshavSoft decouples hosting into three progressive verification stages.

🧭 The Progression Pipeline

// STEP 0: DNS Record at Domain Registrar
GoDaddy / DNS: call ➔ 103.174.102.116
↓
1️⃣ STAGE 1: Smoke Probe (Zero Disk / Zero Code)
npx caddy-subdomain probe call.keshavsoft.com
• Verifies DNS propagation & Let's Encrypt TLS in memory (200 OK)
↓ Proven Live!
2️⃣ STAGE 2: Static File Server (Disk Scaffolding & file_server)
npx caddy-fileserver init call.keshavsoft.com
• Scaffolds /usr/share/call.keshavsoft.com, starter HTML & static route
↓ Need Dynamic Node API?
3️⃣ STAGE 3: Full Dynamic Backend Application
ubuntu-service-cli create & caddy-subdomain add call.keshavsoft.com 5000
• Binds Node.js systemd service and promotes route to reverse_proxy

🎯 Why Decoupling is Essential

By separating hosting into these distinct gates, when a problem occurs, the root cause is 100% deterministic:

If Failure Occurs At... The Root Cause Is... What is NOT Broken
Stage 1 (Probe) DNS propagation delay, port 443 firewall, or Let's Encrypt rate limit. Disk, code, and Node.js ports (they don't even exist yet!).
Stage 2 (File Server) Linux file permissions on /usr/share/ or missing index.html. DNS and SSL (they were already proven in Stage 1).
Stage 3 (Backend API) Node.js process crash or port collision (e.g. 502 Bad Gateway). Network ingress and SSL certificates.
