📖 The Story: The Two Paradigms of Caddy

To understand what we are doing with Caddy across our Ubuntu VPS fleet, you must understand the two ways Caddy operates:

1. The Caddyfile (Config-Driven)

Adapter Layer

A text-based config adapter that most tutorials use. Great for single-site manual editing, but brittle for automation scripts, prone to syntax breakage, and cannot be dynamically inspected.

Read Caddyfile Limitations →

2. Native Caddy JSON (JSON-Driven)

True Source of Truth

Caddy’s canonical internal representation. Enables zero-downtime hot reloads in memory, drives Caddy's REST Admin API (:2019), and allows safe programmatic AST modifications.

Read Native JSON Architecture →
Why We Built Tools on Native JSON
Native JSON is ideal for machines and automation, but deeply nested and difficult for human operators to read and write without making bracket errors. To bridge this gap, KeshavSoft standardized on /etc/caddy/caddy.json and built a complete suite of four focused CLI tools.
Read the Full Toolchain Evolution Story →

📦 The 4 KeshavSoft Caddy Suite Repositories

Each repository in the suite has a single, strictly defined responsibility:

1. caddy-subdomain

Smoke Probes

Level-1 smoke test probe engine. Verifies GoDaddy DNS and Let's Encrypt TLS with an in-memory static_response handler before allocating backend ports. 

npx caddy-subdomain probe call.keshavsoft.com
Handbook Chapter → GitHub ↗

2. caddy-fileserver

Filesystem Bridge

Bridges Caddy TLS (:443) to Ubuntu filesystem (/usr/share/...). Creates document roots, responsive starter HTML, and wires native file_server routes. 

npx caddy-fileserver init call.keshavsoft.com
Handbook Chapter → GitHub ↗

3. caddy-template

Route Blueprints

Emits battle-tested Caddy JSON route AST blocks for reverse proxies (HTTP/WS), split WebSocket daemons, static sites, and multi-domain aliases. 

npx caddy-template proxy appointment.keshavsoft.com 3000
Handbook Chapter → GitHub ↗

4. caddy-cli

Fleet Observability

The Human Lens. Parses live caddy.json to display formatted tables of all active subdomains, upstream dial targets, and occupied ports. 

npx caddy-cli -p
Handbook Chapter → GitHub ↗

Verify GoDaddy DNS & SSL npx caddy-subdomain probe <domain> static_response (200 OK)

🛠️ Emergency Runbook & Ground Truth

1. 502 Bad Gateway

Cause: Caddy accepted traffic on port 443, but the internal backend process is not listening on the target port.

Fix: Check if the backend is running with curl http://localhost:<port> or inspect systemd status.

2. Hot-Reload Without Dropping Active WebSockets

Never run systemctl restart caddy. Use in-memory reload: 

caddy reload --config /etc/caddy/caddy.json

3. Immediate Rollback from Automatic Backups

Every mutation performed by our tools creates a timestamped backup: 

cp $(ls -t /etc/caddy/caddy.json.bak.* | head -1) /etc/caddy/caddy.json
caddy reload --config /etc/caddy/caddy.json
