JSON AST Route Anatomy

A deep, layer-by-layer breakdown of the Caddy JSON Abstract Syntax Tree (AST). Understand how apps.http.servers parses incoming requests down to the exact handler.

Official Upstream Reference: Comprehensive schema definition for Caddy HTTP routes and matchers.
caddyserver.com/docs/json/apps/http/servers/routes/ ↗

🌳 The 6-Level Hierarchy

Every production /etc/caddy/caddy.json file follows this exact hierarchy:

apps
  └── http
      └── servers ("srv0")
          ├── listen: [":443"]
          └── routes: [ <Route 0>, <Route 1>, ... <Route N> ]
                ├── match: [{ "host": ["domain.com"] }]
                ├── handle: [{ "handler": "subroute", ... }]
                └── terminal: true

🔬 Detailed Field Breakdown

Property Type Plain-English Role Production Impact
match.host string[] The SNI hostname(s) this route accepts. Caddy issues Let's Encrypt certificates for every host in this list.
handle[].handler string The root middleware dispatcher. Typically "subroute", allowing multiple child route evaluations.
handle[].routes Route[] Array of inner pipeline handlers. Where path-level matchers (e.g. /ws*) or static response handlers live.
upstreams[].dial string The backend target address:port. Specifies where reverse proxy traffic is routed (e.g. "localhost:3000").
terminal boolean Stops route evaluation. Always set to true so requests that match do not fall through to default fallback handlers.

📄 A Real-World KeshavSoft Route Object

Here is the pristine route AST generated by caddy-template proxy appointment.keshavsoft.com 3000: 

{
  "match": [
    {
      "host": [
        "appointment.keshavsoft.com"
      ]
    }
  ],
  "handle": [
    {
      "handler": "subroute",
      "routes": [
        {
          "handle": [
            {
              "handler": "reverse_proxy",
              "upstreams": [
                {
                  "dial": "localhost:3000"
                }
              ]
            }
          ]
        }
      ]
    }
  ],
  "terminal": true
}
AST Order Matters
In Caddy, routes are evaluated in the order they appear in the routes array. Specific subroutes with path matchers (e.g. /api/* or /ws*) must be placed before catch-all wildcards.
