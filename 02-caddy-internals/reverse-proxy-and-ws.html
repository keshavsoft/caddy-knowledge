Reverse Proxy & Native WebSocket Tunneling

How Caddy handles upstream dial targets, and why Caddy's native bidirectional HTTP/1.1 upgrade tunneling completely eliminates legacy reverse proxy configuration headaches.

Official Upstream Reference: Official documentation on Caddy's reverse_proxy handler module.
caddyserver.com/docs/modules/http.handlers.reverse_proxy ↗

🔄 Automatic WebSocket Upgrades

In older reverse proxies like Nginx, handling WebSockets requires configuring multiple explicit proxy headers: 

# The old, tedious Nginx way:
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_http_version 1.1;

In Caddy, WebSocket proxying is 100% native and automatic. When a client sends an HTTP request with: 

Upgrade: websocket
Connection: Upgrade

Caddy inspects the headers, passes them to the upstream dial target, and hijacks the TCP connection into a full-duplex byte stream. No special flags, headers, or directives are required in your Caddy JSON route.

📐 The Two Architectural Patterns

Pattern A: Unified Port Proxy

Most Common

The backend application (like Express + ws or Socket.io) listens on a single port (e.g. 3000). HTTP requests and WebSocket connections both hit localhost:3000.

Browser (HTTPS/WSS) ──► :443 Caddy ──► :3000 Node.js

Generate with: npx caddy-template proxy domain 3000

Pattern B: Dual-Target Split Proxy

Split Daemons

REST API runs on Port A (e.g. 9011), while an isolated high-throughput WebSocket daemon runs on Port B (e.g. 8080). Caddy splits traffic based on URL path.

Browser ──► Caddy ──┬── /ws* ──► :8080 (WS)
                    └── * ────► :9011 (API)

Generate with: npx caddy-template ws-split domain 9011 8080

🛑 Why Active WebSockets Stay Alive Across Reloads

When you add or update routes and run: 

caddy reload --config /etc/caddy/caddy.json

Caddy's runtime re-initializes only the affected route paths. Existing active WebSocket streams continue running uninterrupted on the established TCP tunnel. This prevents hospital queue displays, appointment calling screens, or trading interfaces from blinking or dropping out during server config updates.
